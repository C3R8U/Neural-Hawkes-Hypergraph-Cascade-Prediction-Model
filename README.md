# Neural-Hawkes-Hypergraph-Cascade-Prediction-Model
This code is a Python algorithm example designed for the task of information cascade prediction. Its goal is to automatically read event sequences from social communication data or scholarly diffusion data, construct propagation cascades, and then learn high-order user relationships, textual semantic changes, and temporal dynamic patterns, ultimately completing next-event user prediction, next-event time-interval prediction, and cascade size prediction.

The input data path of this code is already specified in the configuration. By default, it reads the three files `weibo_dataset.txt`, `twitter_dataset.txt`, and `aps_dataset.txt` from the directory `C:\Users\86156\Desktop`. The code includes a relatively flexible text data loader. It first attempts to parse the TXT files as JSON Lines format. If that fails, it continues to try tab-separated, comma-separated, pipe-separated, or semicolon-separated tabular text formats. If none of these formats can be fully recognized, it falls back to a heuristic line-by-line field extraction method. Therefore, this script does not strictly depend on a single fixed format, but instead tries to remain compatible with common data organization styles. The main logical fields it looks for include `cascade_id`, `user_id`, `timestamp`, `text`, and `depth`. If some fields are missing, the code automatically fills in default values. For example, missing text is replaced with an empty string, missing timestamps are replaced by event order, missing propagation depth is replaced by the event order within the current cascade, and missing users are assigned anonymous user identifiers automatically.

The overall structure of the code can be divided into seven parts: data loading, data preprocessing, hypergraph construction, model definition, loss functions, training and evaluation, and the main program. The data loading part extracts raw event records from the three TXT files and converts them into a unified event object format. The preprocessing part first performs simple tokenization and vocabulary construction for the text, then organizes events into sequential samples according to propagation chains or cascade identifiers, while also mapping users into integer IDs and converting each text into a token ID sequence. It finally generates the training set, validation set, and test set. The hypergraph construction part treats each propagation cascade as a hyperedge and connects all participating user nodes, thereby forming a user–hyperedge incidence matrix, which serves as the input basis for the subsequent variational hypergraph encoder.

In terms of model design, this code implements an approximate engineering version in the style of the paper. The model first uses a Variational Hypergraph Encoder to model high-order user relationships. Instead of simply treating whether two users are connected as a graph edge, it treats multiple users participating in the same propagation cascade as belonging to the same hyperedge, which is more suitable for describing one-to-many and many-to-many group interaction patterns. The encoder outputs the latent distribution parameters for each user, namely the mean and variance, and then samples latent user representations through the reparameterization trick. This step can be understood as learning more compact and continuous user representations from high-dimensional and sparse propagation structures.

The textual semantic component uses a Transformer-based event semantic encoder. The text of each event is first mapped into word embeddings, and then average pooling is applied to obtain an event-level textual representation. To reflect the propagation hierarchy, the code also introduces depth-based positional encoding, which incorporates the event’s level in the propagation tree as a form of structural positional information into the text representation. These event representations are then fed into the Transformer encoder to learn contextual dependencies across the whole propagation sequence. Since propagation semantics usually decay or drift over time, the code additionally includes a learnable temporal decay term to reduce the direct influence of early semantics on later moments, making the implementation closer to the paper’s idea of “dynamic semantic drift.”

The temporal modeling part follows a Neural Hawkes-style implementation. Strictly speaking, the original model in the paper contains a more complete conditional intensity function and a more tightly coupled ODE network process. However, in order to ensure runnability and implementation clarity, this code uses an engineering-friendly approximation. Specifically, the model first concatenates the latent user representation and the current event semantic representation, and then projects them into a unified hidden space. Whenever an event occurs, the hidden state is updated once using a GRUCell to absorb the information from the current event. The continuous temporal evolution between two events is then simulated by a small ODEFunction module, which updates the hidden state through a multi-step Euler-style approximation, thereby reflecting the idea that “the system state continues to evolve even between observed events.” At each step, the model predicts the next responding user, the next event time interval, and finally the overall cascade size at the end of the sequence.

The loss function is composed of multiple jointly optimized parts. First, there is a cross-entropy loss for next-user prediction, which is used to learn “which user is most likely to trigger the next event.” Second, there is a time-interval prediction loss, where the code applies a `log1p` transformation to the time interval before computing mean squared error, in order to reduce the impact of very large interval samples. Third, there is a cascade-size prediction loss, which also uses mean squared error in logarithmic space. In addition, there is a hypergraph structure reconstruction loss that constrains the variational encoder to recover user co-occurrence relationships as much as possible. Finally, a KL divergence term is added to keep the latent variable distribution smooth and consistent with the requirements of variational modeling. With these components combined, the model can simultaneously learn topological relationships, semantic evolution, and temporal behavior.

The configuration parameters of the code are centrally defined in the `Config` class, which makes them convenient to modify. The `data_dir` parameter specifies the dataset directory, while `dataset_files` specifies the file names to be loaded. `max_vocab_size` and `min_token_freq` control the vocabulary size and minimum token frequency, and `max_text_len` controls the maximum number of tokens retained for each text. `embed_dim` is the semantic representation dimension, `latent_dim` is the hypergraph latent-variable dimension, and `transformer_heads` and `transformer_layers` control the number of attention heads and layers in the Transformer, respectively. `dropout` controls the regularization strength, while `lr` and `weight_decay` control the optimizer settings. `num_epochs` determines the number of training epochs. `train_ratio` and `val_ratio` control the train–validation split. `hidden_dim` is the dimension of the joint hidden state, and `ode_steps` determines into how many substeps each time interval is discretized to approximate the ODE evolution. If your machine has limited computational resources, you can reduce `embed_dim`, `hidden_dim`, `transformer_layers`, or `num_epochs` to lower the computational cost.

The usage of this code is relatively straightforward. First, make sure that `torch` and `numpy` are installed in your Python environment. After installation, place the script file and the three dataset files in the specified directory, or directly modify `data_dir` in the code to your actual path. Then run `python nhhpp_cascade_model.py` in the command line to start the program. When the program starts, it first prints device information, indicating whether it is using a CPU or a GPU. It then sequentially loads the three datasets, builds the vocabulary and user mappings, generates training samples, constructs the hypergraph incidence matrix, initializes the model, and begins training. At the end of each training epoch, the program outputs the training loss, validation loss, user prediction accuracy on the validation set, time MAE, and cascade size MSLE. After training is finished, it also outputs the final metrics on the training, validation, and test sets, and provides an example prediction for one test cascade sample, including the predicted next-user sequence, next-event time intervals, and predicted final cascade size.
